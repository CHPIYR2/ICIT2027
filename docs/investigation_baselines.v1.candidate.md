# Investigation Protocol v1 — controlled baseline matrix

Version: baselines-v1-candidate-20260925. The current author instruction supersedes
the older B1–B4 meanings. No baseline B1–B4 is implemented or executed here.

| Baseline | Primary evidence | Generation | Citation instruction | Verifier |
|---|---|---|---|---|
| B0 | EN | Existing deterministic structured investigation | Existing traceable evidence links | Existing B0 finite consistency checks only |
| B1 | N only | One pending fixed LLM snapshot | Optional, same as B2 | None |
| B2 | EN | Same LLM as B1 | Optional, same as B1 | None |
| B3 | EN | Same LLM as B1/B2 | Required for substantive assertions | None |
| B4 | EN | Replay the corresponding B3 output, generated by that same LLM | Identical B3 citations/input | Deterministic verifier + canonical publish/qualify/withhold |

B1→B2 is cross-source investigation value. B2→B3 is citation/grounding value.
B3→B4 is deterministic verification/publication value, paired on the identical raw
B3 output rather than confounded with a new generation. B4's LLM component is the
same model used by B1–B3; it does not introduce a second model or call an LLM judge.
There is no separate question-sufficiency model arm or model-comparison experiment.

B0's already generated N/E views remain historical diagnostics, not extra primary
arms. Primary B0 uses EN. The planned evaluation matrix is 32 events × 5 primary
baselines = 160 event-baseline cells, before repeated runs. This is a design count,
not a research result; repetitions, cost and scheduling remain pending.

Controls required at final freeze:

- Identical provider/model snapshot, temperature, seed policy when supported,
  max input/output tokens and output schema for B1–B4.
- Identical question text, persona, task wording, numeric rendering requirement
  and input ordering except B1's N-only mask and B3's explicit citation obligation.
- Same event anchor/window, authorized M, extraction version and fixed total
  serialization budget. Existing N = up to 64 N entries; EN = up to 32 N + 32 E;
  both at most 48,000 compact JSON bytes. M counts toward bytes, not record quota.
  B2/B3/B4 use exactly the same EN bundle and receipt; B4 reuses B3 verbatim input.
- Report the EN/N quota tradeoff: B1→B2 estimates cross-source system value under
  fixed total budget, not the isolated effect of adding E while holding every N
  record constant. The approved EN retriever prioritizes same-asset E and is part
  of that system. No superiority is claimed before the experiment.
- Model-specific tokenizer and total serialized prompt limits are still pending.
  If the selected model cannot fit the existing bundle, decide a deterministic
  common budget/serialization revision using development only before freeze; do
  not silently truncate differently across B2/B3/B4 or tune using evaluation.
- Preserve invalid outputs, refusals and transport failures, with a predeclared
  retry policy. No best-of selection or evaluator-assisted citation repair.
- B4 comparison measures the full deterministic validation/publication step,
  including qualification/withholding. Report retained content/coverage alongside
  overclaim reduction. It is not proof of arbitrary free-text semantic verification.

The reviewed gold uses electrical_change while existing B0 numeric outputs use
reported_change. Exact matching makes this an explicit representation issue;
the author must resolve the pending B0 representation decision before final
scoring. No reviewed fact or old B0 artifact is changed in preparation.
