# Related work

Each note says what the paper does, then what ETGI does not inherit. Iterative retrieval, graph-guided investigation, and temporal graphs already exist. ETGI does not claim them as firsts.

## PROVSEEK

Mukherjee et al., arXiv:2508.21323, 2025. Task: provenance forensics and threat detection on host traces, evaluated on DARPA Transparent Computing. Algorithm: several role-specific agents; RAG over threat reports; type-specific SQL against a provenance database; an autoencoder that drops frequent benign events; artifact and event resolvers that bind claims to node and edge ids. The loop refines hypotheses and checks them against retrieved events. LLM agent: yes. Event graph: the database is already a provenance graph; the system queries it rather than building an OT incident graph. Multimodal: process, file, and network provenance, not electrical telemetry. Evidence check: SQL plus id binding, not a second model's opinion. Evaluation: contextual precision and recall against intelligence extraction, and detection precision and recall against provenance intrusion detectors. Limit: the agent writes or selects database queries, depends on CTI text, and has no account of a measurement that is only a second view of the same packet. Difference: ETGI's model cannot write SQL. Its checks are fixed record rules, and a network-decoded point is not counted twice. PROVSEEK already has iterative evidence retrieval; that part of ETGI is not new.

## CyberSleuth

Fumero et al., arXiv:2508.20643, 2025. Task: post-mortem forensics of web attacks from PCAP, plus a transfer check on malware traffic. Algorithm: a MemGPT-style pipeline of specialised agents with tshark, a flow summary, and web search. The paper compares single-agent, nested, and simple sequential orchestration. LLM agent: yes. Event graph: no incident graph with revision history. Multimodal: packet traces only. Evidence check: the agent extracts indicators and maps them to CVEs; 25 experts rate reports. Evaluation: service identification, exact CVE accuracy, attack success, and expert ratings on 30 controlled cases. The best reported CVE result on the 2025 split is 80 percent. Limit: the task has a CVE gold label, uses web search, and the authors treat prompt and memory design as part of the method. Difference: ETGI does not search the web, does not map traffic to CVEs, and does not treat prompt variants as the experiment. It keeps a revisable evidence graph and tests whether removing a cited record changes the judgment.

## GALA+

Tian, Liu, Chong, Huang, Li, and Jacobsen, arXiv:2608.08968, 10 August 2026. Task: microservice root-cause analysis and incident response. Algorithm: STRIX ranks services from trace latency, PageRank-style centrality, and an impact score, fused with a metrics ranking. Parallel investigator agents start at the top candidates and expand to graph neighbors only when the agent's confidence is below 0.6, with a bounded fan-out. LLM agent: yes. Event graph: the service dependency graph constrains the search. Multimodal: metrics and traces. Evidence check: agent confidence plus chain coherence. The paper's SURE-Score uses human SRE judgments and an LLM judge. Evaluation: AC@1 on two microservice benchmarks, reported as more than 25 points above the best LLM baseline, plus human ratings. Limit: confidence is the model's own score, the graph is a known service topology, and the output is a ranked root cause rather than an evidence-revised association that may stay unresolved. Difference: ETGI has no service topology and does not treat model confidence as a probability. GALA+ already studies graph-guided multimodal investigation; ETGI's different piece is the source-dependence rule and the evidence-removal test on OT telemetry.

## Microsoft GraphRAG

Edge et al., arXiv:2404.16130, 2024. Task: global questions over a private text corpus. Algorithm: an LLM extracts an entity graph, community detection builds a hierarchy, and community summaries are map-reduced into an answer. LLM agent: the model extracts and summarizes; it is not an incident investigator with tools over packets. Event graph: an entity graph of documents. Multimodal: text. Evidence check: LLM-as-judge for comprehensiveness and diversity, not a database audit. Evaluation: sensemaking questions over corpora near one million tokens, compared with vector RAG. Limit: no timestamps of measurements, no contradiction search, and the judge is a model. Difference: the ETGI baseline called B2 only retrieves rows already cited by record-link edges. It does not extract entities, detect communities, or summarize them. It is not a reproduction of GraphRAG.

## Zep / Graphiti

Rasmussen et al., arXiv:2501.13956, 2025. Task: agent memory across conversations. Algorithm: Graphiti stores episodes, semantic entities, and communities. Edges carry a valid-time interval and an ingestion time. Entity resolution uses embeddings and an LLM; writes use fixed Cypher rather than model-written queries. LLM agent: the graph is a memory layer for agents. Event graph: a temporal knowledge graph of dialogue and business records. Multimodal: text and JSON, not packet captures. Evidence check: entity resolution and bi-temporal invalidation, evaluated on Deep Memory Retrieval and LongMemEval. Limit: facts come from language, not from a capture that can be re-read. Difference: ETGI's history records why an incident edge was revised after a record check. It is not a general memory store and it does not embed entity names.

## HippoRAG 2

Gutiérrez et al., ICML 2025, PMLR volume 267. Task: multi-hop question answering. Algorithm: open information extraction builds a phrase-passage graph; retrieval uses Personalized PageRank and a recognition-memory filter. LLM agent: the model extracts triples and answers; retrieval itself is graph search. Event graph: a document knowledge graph, not an incident timeline. Multimodal: text. Evidence check: answer accuracy and retrieval recall on QA benchmarks. Limit: passages are not measurement records with provenance. Difference: ETGI does not train or query an embedding index, and it does not claim multi-hop graph retrieval as a contribution.

## ExCyTIn-Bench

Wu et al., PMLR volume 306, 2026. Task: evaluate cyber-investigation agents on questions whose answers can be checked in security telemetry. Algorithm: the benchmark, not a new investigator. Agents may search logs and are scored on investigation questions. LLM agent: the systems under test are agents. Event graph: not required. Multimodal: enterprise security logs. Evidence check: question gold, rather than a model deciding that its own report is correct. Evaluation: accuracy on those questions. Limit: the corpus is not Sherlock and the questions are not about IEC-104 provenance. Difference: ETGI copies the evaluation idea. Gold is computed from the indexed window before the investigator answers, and a method receives credit only for ids it actually retrieved. This is not a run of ExCyTIn-Bench.

## FActScore

Min et al., EMNLP 2023. Task: factual precision of biographies. Algorithm: split a generation into atomic claims and test each claim against a knowledge source, with humans or a model. LLM agent: no investigation loop. Event graph: none. Multimodal: text. Evidence check: support of atomic claims. Evaluation: the fraction of claims that the source supports. Limit: a model judge can disagree with the source, and the source is an encyclopedia rather than a capture. Difference: ETGI checks evidence ids, timestamps, and numeric values with queries. A second model is not the ground truth.

## RAGChecker

Ru et al., NeurIPS 2024. Task: fine-grained evaluation of retrieval-augmented generation. Algorithm: decompose the answer and the context into claims and score entailment, including faithfulness to the retrieved context and coverage of a reference. LLM agent: no. Event graph: no. Multimodal: text. Evidence check: natural-language entailment. Evaluation: diagnostic precision and recall of claims. Limit: entailment does not know that two rows are the same packet. Difference: ETGI reports retrieval coverage of SQL gold and record-link failures. It does not run the RAGChecker entailment model, so those scores are not claimed.
