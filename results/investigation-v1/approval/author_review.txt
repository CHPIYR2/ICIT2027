# 1. Mandatory command-target feasibility audit

The repository audit found that current canonical network evidence does not preserve usable command-to-asset linkage.

Current limitations include:

- packet/message asset_id is None;
- command CA/IOA is not preserved in the canonical network evidence;
- command setpoint/select-execute information is not preserved;
- a command observation therefore cannot currently be linked to a target asset.

This may substantially weaken cross-source OT incident investigation.

Before final protocol freeze, perform a narrow feasibility audit using raw allowed Sherlock evidence.

Determine whether IEC-104 command ASDUs (types 45–51) contain reliably parseable:

```text
Common Address (CA)
Information Object Address (IOA)
```

and whether those identifiers can be mapped through the existing sanitized mapping to an opaque asset/control point without using:

```text
gold attack_point
event family
malicious label
scenario playbook
physical simulator truth
hidden evaluator metadata
```

Do not expose command setpoint values merely to solve this problem unless separately justified.

Create:

```text
docs/command_target_feasibility.md
```

The document must answer:

1. What exact raw bytes / parser fields contain CA and IOA for command ASDUs?
2. Does the existing mapping contain a valid corresponding entry?
3. Is the mapping static operational metadata M or evaluator-only G?
4. Can a target asset/control point be represented with sanitized opaque IDs?
5. What fraction of candidate investigation events contain commands for which this mapping is available?
6. Are there ambiguous, duplicated, configuration/measurement-colliding, or unmapped addresses?
7. Can this be implemented without changing the previous classification results/contracts?
8. What new leakage risks would it create?

Do not infer command execution from target mapping.

Do not infer causality.

Do not infer malicious intent.

## If feasible

Propose, but do not silently implement, an amendment to `command_observed` such as:

```text
command_observed
- command evidence ID
- ASDU type
- COT
- CA
- IOA
- mapped_target_id: optional opaque asset/control-point ID
- observation time
```

The strongest permitted statement should be equivalent to:

> A command-type activation request addressed to the mapped control point of asset X was observed.

It must NOT support:

> asset X executed the command

or:

> the command caused the later process/electrical change.

Also propose how `asset_relationship` and `temporal_association` would use this mapping.

## If not feasible

Do not invent the mapping.

Record this as a dataset/evidence limitation.

Revise RQ1 interpretation so that cross-source reconstruction means cross-domain timeline/context completeness, not asset-linked causal reconstruction.

# 4. Retrieval accounting

Maintain the proposed primary retrieval budgets:

```text
E-only: 64 E entries
N-only: 64 N entries
E+N: 32 E + 32 N entries
```

However, every evaluation must preserve three separate quantities:

```text
eligible evidence universe
retrieved evidence bundle
final recovered investigation facts
```

This is necessary to distinguish:

```text
evidence unavailable in a view
retrieval truncation/failure
LLM reasoning failure
```

For every gold fact later record:

```text
supportable from eligible universe?
complete support retrieved?
correctly recovered by system?
```

Do not attribute retrieval loss to multimodal reasoning.

# 7. Preserve the current semantic boundaries

Continue enforcing:

```text
command observed ≠ command executed

acknowledgement observed ≠ physical success

electrical/process change observed ≠ attack-caused change

temporal association ≠ causation

missing evidence ≠ benign

classifier prediction ≠ investigation evidence
```

The deterministic verifier remains an evidence-consistency/support checker, not a semantic truth oracle.

---

Implement the deterministic timeline baseline first.

# Research principle

The objective is not to make an LLM produce a convincing incident narrative.

The objective is to determine whether OT incident investigation can remain useful while every substantive conclusion is traceable to observable electrical/network evidence, mechanically checked where possible, and explicitly weakened or withheld when the available evidence is insufficient.
